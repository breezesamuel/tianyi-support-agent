## 8. 第三轮深挖（2026-11-17）

第三轮不再追求功能数量，而是对照竞品在**合规、安全、质量度量、可访问性**四个"上线才会被审计/投诉"的深水区逐项补齐。

### 8.1 新增调研维度与竞品做法

| 维度 | 竞品 2026 做法 | 本轮应对 |
|---|---|---|
| AI 身份透明 | EU AI Act 第50条（2026-08 生效）：直接与人交互的 AI 必须告知用户身份，违规最高罚 1500 万欧元或全球营收 3% | 访客端常驻"您正在与 AI 助手对话"披露条，后台可开关与改文案，中英双语 |
| PII 检测脱敏 | Lorikeet / Questa / Fora Soft：手机号、身份证、卡号、邮箱在进入模型、日志、分析前 token 化；可回放的脱敏审计 | 正则规则版识别 5 类敏感信息，支持中间脱敏/占位符/仅告警三模式，写入会话前脱敏并记审计 |
| 质检评分卡 | Intercom Monitors + Custom Scorecards、Fin CX Score（1-5）、Forethought QA（100% 评分）：按可配置维度权重给每条会话打分，关键项可一票否决 | 可配置 4 维度权重评分卡（答案有据/合规安全/问题解决/服务态度），每条会话自动 1-5 分，关键项失败不通过，后台质检明细表 |
| 真实解决率 | Fin/Zendesk 对"封闭率（containment）"与"真正解决"的口径之争：客户停止回应≠问题解决；Gorgias/ZeninTech 强调重复联系率 | 新增会话封闭率、已验证解决率、被高估部分、知识库无命中率、7 日内重复咨询率，明确区分两种口径 |
| WCAG 2.2 无障碍 | EU AI Act/EAA/ADA：aria-live 播报、键盘可达、可见焦点、字号与对比度、减少动效；语音不能是唯一路径 | skip link、aria-live 播报区、键盘快捷键（Alt+N/Alt+/ /Esc）、大字号、高对比度、减少动效、可见焦点环，且保留文字输入 |
| 语音输入 | Web Speech API（Chrome/Edge/Safari 支持，Firefox 不支持），需可见状态与文字降级 | 浏览器语音识别按钮，带录音状态动画与播报；不支持时自动降级为文字并提示 |

### 8.2 第三轮已落地模块（6 项）

1. **AI 身份披露条**：符合 EU AI Act 第50条透明度的常驻提示，后台可配置。
2. **PII 检测脱敏**：5 类敏感信息 × 3 种策略，入库前脱敏 + 可审计，覆盖用户消息进入大模型之前的链路。
3. **结构化质检评分卡**：4 维度可配权重、关键项一票否决、自动 1-5 分、后台质检明细与通过率。
4. **真实解决率指标**：封闭率 vs 已验证解决率 vs 被高估部分，无命中率与重复咨询率，写进口径说明。
5. **WCAG 2.2 无障碍**：skip link、aria-live 播报、键盘快捷键、大字号、高对比度、减少动效、可见焦点。
6. **语音输入**：Web Speech API 渐进增强，含不支持时的文字降级路径。

### 8.3 仍存在的差距（诚实说明）

- **PII 正则的局限**：正则无法 100% 覆盖自由文本中的姓名、地址等非结构化 PII，也无误杀平衡；生产需 NER 模型 + 单向哈希 + 分角色短时提权，本实现仅为规则版防护。
- **语音仅输入**：本轮语音是浏览器端语音转文字（SpeechRecognition），非端到端 Voice AI 坐席； synthesis 播报、电话网关、声纹验证未实现，Firefox 不支持。
- **QA 为规则评分**：评分卡基于可解释规则（是否引用来源、是否命中敏感词、是否解决、情绪处理），非 LLM 语义评分；无人工复核工作流与抽样策略配置。
- **无障碍为自助实现**：已覆盖关键 WCAG 2.2 条款，但未做 axe-core 自动扫描与真实读屏软件（NVDA/VoiceOver）用户测试，自动化仅能发现约 30% 问题。
- **服务端/全渠道/多语言深度**：与第二轮结论一致，CRM/支付/SSO/WhatsApp/实时翻译需后端与外部账号，纯静态应用无法覆盖。

### 8.4 第三轮验证

- 四个 JS 文件 `node --check` 通过，无硬编码密钥。
- Node 桩测试通过：PII 检测与三模式脱敏、QA 评分（含合规一票否决与分数线配置）、真实指标、a11y 持久化、导出脱敏。
- 全 DOM id 桩验证通过：admin.html 12 个页面 section、index.html 访客端，所有 `el()` 引用命中且初始化无运行时错误。

## 9. 第四轮深挖：统一收件箱与坐席协作（2026-11-17）

第三轮之前虽在路线图中规划了「统一收件箱」12 项 P1 模块，但核对源码发现仅停留在文档、未真正落地。第四轮把这些承诺补齐为可用的产品能力，聚焦「后台不只是看，而是能运营」。

### 9.1 落地模块（14 项）

1. **统一收件箱工作台**：会话列表支持 VIP 置顶、队列筛选（VIP / 排队中 / 我的），把「看对话」升级为「分配与处理」。
2. **VIP 优先**：会话可标记 VIP，列表置顶并优先排队；批量标 VIP。
3. **会话排队 + 位置提示**：转人工进入队列（VIP 优先 + 入队时间排序），访客端实时显示「排在第 N 位 / 共 M 人」。
4. **会话转接**：坐席之间转接，记录 from→to 历史并写内部备注，转接后退出排队。
5. **会话合并**：多条会话的消息、标签、备注并入目标会话，来源会话软删除且工单同步迁移。
6. **会话拆分**：按勾选消息拆出新会话，保留访客画像与意图。
7. **@同事**：在会话内 @坐席姓名生成提醒，含未读计数与已读标记。
8. **碰撞检测**：坐席打开会话时登记查看锁，窗口期内其他坐席查看会收到提示，避免重复回复。
9. **草稿同步**：坐席回复草稿按会话自动保存，切换会话不丢失。
10. **回复宏**：一次点击顺序执行「打标签 / 插话术 / 分配 / 写备注 / 改状态」多步动作。
11. **回复模板**：支持 `{{visitor}} {{intent}} {{agent}} {{date}} {{order}}` 变量的模板，一键插入草稿。
12. **批量会话操作**：多选后批量分配、加标签、标 VIP、标已解决、删除。
13. **关键词自动回复**：命中关键词直接答复，优先级高于知识库与大模型，最短路径解决问题。
14. **离线自动回复**：非服务时间（含跨天时段）转人工时自动给出服务时间与留资提示。

### 9.2 仍存在的差距（诚实说明）

- **消息形态增强未做**：富文本、图片/文件/语音/视频消息、链接预览、消息撤回/编辑、已读回执、输入指示器仍为缺失或部分，需文件存储与后端支持。
- **协作为单机模拟**：碰撞检测、草稿、@提醒基于本地存储，多坐席真实协同需服务端推送（WebSocket）与账号体系。
- **排队为展示层**：排队位置按本地规则计算，非分布式队列；真实并发排队与坐席工作台需后端。

### 9.3 第四轮验证

- 四个 JS 文件 `node --check` 通过，无硬编码密钥。
- Node 桩测试 21 项数据层能力全部通过（VIP / 排队 / 转接 / 合并 / 拆分 / @提及 / 草稿 / 宏 / 模板 / 批量 / 关键词等）。
- 访客流程桩测试 9 项通过（关键词命中与开关、VIP 插队、服务时间与离线文案）。
- DOM id 桩验证：admin.html / index.html 所有 `el()` 引用命中（动态生成 id 已核对），无运行时错误。

## 10. 第五轮：GitHub Agent Skill 调研与方法论集成（2026-11-17）

按用户要求赴 GitHub 检索 1000+ Agent Skill，筛选后集成。真实数据：sickn33/agentic-awesome-skills 索引 2,981 个 skill（safe 1,110 / critical 1,614 / offensive 151），另有 anthropics/skills 官方库（196k★）、VoltAgent/awesome-agent-skills（1,000+）、ComposioHQ/awesome-claude-skills（79.7k★）。详见 `docs/github-skills-integration.md`。

### 10.1 关键认知与集成方式

- 这些 skill 是给 Claude Code/Cursor/Codex 等**编程 Agent** 的方法论指令（SKILL.md），不是可塞进网页运行的插件。因此采用「提炼 safe skill 方法论 → 转化为客服 Agent 真实能力」的方式，而非假装安装。
- **风险筛查**：样本中 54% 为 critical/offensive，仅采纳 `risk=safe` 且来源明确的 skill，未引入任何高风险项或需服务端凭证的代码。

### 10.2 落地能力（6 项）
